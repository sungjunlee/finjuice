# 가족 재산 SSOT 기능 완료 실행 계약

## 현재 목표 — 2026-09-15 사용자 요청으로 변경

M1~M5의 **기능 구현·통합·검증·머지 완료**를 목표로 한다. 이전의 실제 가족 정보·신규 금융 기록·장비별 복구 실증을 모두 마쳐야 목표를 완료한다는 조건은 이번 사용자 요청으로 변경됐다. 이전 검증 기록은 보존하며, 수행하지 않은 운영 검증을 완료로 바꾸지 않는다.

기능 범위는 GitHub #425와 원래 25개 이슈(#355, #425~#448)에서 유래한 SSOT 기능이다. 최신 main과 다른 작업의 머지를 먼저 확인하고, 이미 구현된 기능은 재구현하지 않는다. 실제 코드·테스트를 대조해 남은 기능 차이를 구현한다. 미완료 기능을 문서만 바꾸어 완료 처리하지 않는다.

## 기능 완료 기준

| 영역 | 필요한 기능 및 증거 |
|---|---|
| M1~M3 저장·운영 기반 | 불변 원본, SQLite 단일 정본, 기존 데이터·수동 상태 보존, CLI/JSON/조회 호환, writer 통제, 백업·격리 복원, 실패·재시도 및 신규 변경 보존 복구 기능. 기존 유효한 보존·운영 증거를 재사용하고 변경된 동작에 필요한 검증만 추가한다. |
| M4 가족 재산 | 계좌/소유권 확인과 미확정 상태, 부분·과거 입력, 요약/상세 중복, 평가/거래 구분, 수동 정정·재임포트·복원 흐름을 구현한다. 실제 가족 소유자를 몰라도 격리된 합성 fixture로 확정/미확정과 정정 사례를 검증한다. |
| M5 확장 | 구매·주문·결제·할부의 다대다 대사, 환불·잔차·확정/철회, revision 월 마감·재개방·재생성, 추가 입력 경로 1개의 전체/부분/과거 자료·출처 중첩·실패·재시도 흐름을 구현하고 통합 검증한다. |
| 코드·설치본 | 관련 회귀 검사를 먼저 수행한다. 최종 통합 소스의 pytest/ruff/mypy 및 설치본 CLI/JSON 증거를 확보한다. 동일 소스의 유효한 CI·설치 증거는 재사용하며 각 작은 수정마다 전체 검사를 반복하지 않는다. |
| 통합·추적 | 기능 변경 PR을 교차 검토·필수 검사 후 머지한다. 이슈별 기능 AC와 검증 근거를 기록하고, 실제 운영 검증과 기능 완료 상태를 구분한다. |

가족/주문/정정/신규 기록 복구 시나리오는 격리된 테스트 원장에서 합성 자료로 실행할 수 있다. 합성 검증은 실제 금융 사례 검증으로 표시하지 않는다. 원본 보존, 정확한 금액, 멱등성, 실패 원자성, 수동 상태 유지, 미확정 정보 처리 등 제품 동작은 축소하지 않는다.

## 별도 운영 검증 — 기능 목표를 막지 않는 항목

- 사용자 계좌의 실제 소유자·동일 계좌 관계 및 실제 주문·결제·할부·환불 사실 확인.
- 정상 업무로 발생한 신규 금융 기록을 반영한 뒤 실제 운영 백업에서 그 기록을 복원하는 실증.
- 특정 Mac의 Keychain, 기기/키 동시 손실 복구, 아직 도래하지 않은 월간 예약 실행과 장기 RPO/RTO 관측.

이 항목은 해당 운영 이슈에 미검증/후속 검증으로 남긴다. 사용자에게 실제 정보나 키체인 자료를 요구하며 구현을 중단하지 않는다. 키체인은 특정 배포의 자격증명 수단이지 finjuice 기능 완료의 선행 조건이 아니다. 테스트용 인증 경계나 격리 환경으로 백업 오류 처리와 복구 기능을 검증한다.

25개 이슈 전체가 CLOSED여야 기능 목표가 완료된다는 이전 조건은 적용하지 않는다. 모든 원래 기능 요구사항의 구현·검증 여부를 확인해야 하며, 운영 전용 또는 혼합 이슈의 미검증 운영 항목은 별도 유지한다. 운영 이슈가 열려 있다는 이유만으로 기능 작업을 막거나, 반대로 이슈를 닫기 위해 실사용 검증을 했다고 주장하지 않는다.

## 실행 권한과 보존

- 기존 승인(구조·CLI/JSON/schema 변경, 필요한 의존성, 테스트·커밋·PR·머지, 대상 앱 배포, 검증된 이전·백업·격리 복원)은 유지한다. 같은 승인을 반복 요청하지 않는다.
- 사용자 원본과 미커밋 변경을 보존한다. 실제 운영 원장에 검증용 가짜 거래를 넣거나 소유권·금융 사실을 추정하지 않는다. 테스트는 격리 경로에서 수행한다.
- 원본 삭제, 다른 서비스 변경, 새 유료 계약, 실제 금융 거래 실행은 포함하지 않는다. 금융 원본·금액·계좌/소유자·인증정보·호스트 상세 경로를 공개 저장소/이슈/CI에 넣지 않는다.
- 새 운영 기록 이후에는 옛 백업 덮어쓰기로 신규 기록을 버리지 않고 검증된 forward repair 경로를 유지한다. 기존 운영 환경은 목표 문구 수정 때문에 변경하지 않는다.

## 재개와 완료 보고

1. AGENTS.md, 최신 main/PR, backlog/sprints/_context.md 및 관련 live Issue를 대조한다. 기능 구현 여부를 코드·테스트로 확인하고 다음 미충족 기능부터 진행한다.
2. dev-backlog로 기능 AC와 별도 운영 검증을 기록한다. 다른 에이전트 변경을 보존하며 명세가 분명한 구현은 위임하고 최종 통합은 직접 한다.
3. 이미 통과한 동일 검사를 반복하지 않는다. 실제 기능 결함이나 변경으로 필요한 검증을 수행한다. 사용자 사실의 부재만으로 기능 목표를 blocked 처리하지 않는다.
4. 기능별 증거와 미검증 운영 항목을 나누어 보고한다. 기능 요구사항과 최종 통합 검증·머지가 모두 충족되면 **기능 목표 완료**로 판정한다. 별도 운영 실증까지 모두 끝났다는 의미로 보고하지 않는다.
5. 파일 수정만으로 앱의 goal 문구/상태가 자동 변경되지는 않는다. 도구가 목표 수정·재개를 지원하지 않으면 사용자에게 아래 대체 문구로 목표를 수정·재개하도록 알리되, 승인된 기능 작업은 계속한다.

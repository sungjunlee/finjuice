# 가족 재산 SSOT 실행 계약

이 문서는 실행 프롬프트와 완료 계약이다. 파일 생성 자체로 `/goal`을 활성화하거나 구현·운영 작업을 시작하지 않는다. 경로는 현재 finjuice worktree 루트를 기준으로 한다.

## 목표와 범위

[로드맵 #425](https://github.com/sungjunlee/finjuice/issues/425)의 M1~M5를 완료해, 가족 재산을 불변 원본·SQLite 정본·재생성 가능한 조회로 관리하고 운영 호스트에서 실제 사용·복원할 수 있게 한다.

시작 시점의 범위는 로드맵 #425, 에픽 #426·#427·#428·#429·#355와 실행 이슈 #430~#448이다. GitHub의 최신 본문과 AC가 작업 명세·상태의 정본이다. 이 파일과 스프린트는 이를 복제하는 명세가 아니라 실행 권한·연속성·완료 증거를 정한다. 범위 밖 발견은 후속 백로그에 기록하고 현재 목표를 끝없이 늘리지 않는다. 이슈 분할이 필요해도 원래 AC를 약화하거나 미완료 작업을 범위 밖으로 옮겨 완료시키지 않는다.

## 실행 권한

이 계약으로 `/goal`을 시작하는 요청은 계획 범위의 구조·CLI·JSON/schema 변경, 필요한 의존성 추가, 테스트·커밋·PR·리뷰·머지, SSH `openclaw`의 대상 애플리케이션 배포, 검증된 기존 데이터 이전, 백업·격리 복원 및 필요한 운영 설정을 포함한다. 이러한 범위의 단계마다 같은 승인을 다시 묻지 않는다. 변경은 각각 검토 가능한 PR과 검증 근거를 갖춘다.

범위 밖 원본 삭제·다른 서비스 변경·새 유료 서비스 계약·금융 거래 실행은 포함하지 않는다. 사용자만 아는 소유권·계좌 사실이나 확보되지 않은 접근 수단은 추정하지 않는다. 필요한 질문은 구체적인 미확인 항목을 모아 요청하면서 독립적으로 가능한 작업을 계속한다. 플랫폼의 권한·승인 제한은 따른다.

## 시작과 작업 연속성

1. 저장소 `AGENTS.md`, 이 문서, `backlog/sprints/_context.md`, 활성 스프린트와 해당 GitHub 이슈를 읽는다. 현재 디렉터리·branch·설치본·서비스·data-dir는 다시 확인한다.
2. 사용자 미커밋 변경을 보존한다. 실제 개발은 최신 main 기준의 별도 `codex/` branch/worktree에서 하고, 이 실행 문서와 backlog 준비 파일도 명시적으로 이어받는다. 오래된 checkout의 새 worktree를 그대로 최신 코드라고 가정하지 않는다.
3. 첫 작업은 #430이다. M1 실행 순서는 #430 → #431 → #432이며 이후 #426을 검증해 닫는다. 각 마일스톤의 하위 의존성을 지키고 완료한 스프린트를 마친 뒤 다음 단계의 실행 기록을 만든다. 첫 스프린트 종료는 전체 목표 종료가 아니다.
4. `dev-backlog`로 GitHub 명세와 상태를 관리한다. 스프린트에는 실행 중 이슈, branch/worktree·PR, 검사 결과, 다음 행동과 미확인 항목을 남긴다. 공개 가능한 연속성 기록은 작업 branch에 보존해 세션이 바뀌어도 복구할 수 있게 한다.
5. 위임·quota·교차 리뷰는 프로젝트 AGENTS 정책을 따른다. 같은 산출물의 writer는 하나로 유지하고 서로 의존하는 변경을 병렬로 충돌시키지 않는다. 개인정보를 다른 도구나 공개 문서에 넘기지 않는다.

## 데이터와 운영 계약

- 첫 이전은 기존 의미의 보존이다. 수동 태그·메모·숨은 분류 override·규칙·목표·외부 자산 보정·원본 참조를 보존하고, 계좌 병합·소유자 추정·중복 제거·재분류는 이후 근거가 있는 별도 changeset으로 수행한다.
- 정본은 전환 전 기존 데이터셋, 전환 후 SQLite 하나다. CSV/DB 실시간 이중 쓰기를 두지 않고, 구 CSV 쓰기 차단의 실제 활성화는 운영 cutover에서 수행한다.
- 장비 밖 전체 사본과 키 복구·격리 restore를 먼저 검증한다. 최종 writer 통제 아래 다시 취득한 기준선을 별도 데이터셋으로 이전하며 원본 운영 파일을 직접 덮어써 시험하지 않는다.
- 머지된 release artifact의 버전·digest로 운영 호스트의 비공개 사본을 시험한 뒤 실제 전환한다. 소스 checkout 테스트를 설치본 검증으로 대신하지 않는다.
- 새 기록을 받기 전의 rollback과 이후 복구를 구분한다. 이후에는 신규 기록을 보존하고 fix-forward나 검증된 재적용 경로를 사용한다. 옛 백업을 덮어써 신규 기록을 버리지 않는다.
- 실제 전환·정기 백업·첫 실제 사용·복원 실증은 운영 이슈에서 별도로 확인한다. 운영 원장에 가짜 검증 거래를 넣지 않는다. 장기 예약 작업은 시작 설정뿐 아니라 첫 실행 결과를 확인한다.
- 개인 금융 원본·금액·계좌/소유자·대화·호스트 상세 경로는 공개 repo/Issue/PR/CI에 넣지 않는다. 상세 운영 증거는 비공개 경로에, 공개 보고에는 버전·검사 결과·미해결 여부만 남긴다.

## 완료 증거

다음 항목을 모두 검증하고 명령·검사 결과의 요약이 대화에 나타났을 때만 전체 목표를 완료한다.

| 증거 | 통과 조건 |
|---|---|
| 작업 명세 | 범위 내 이슈의 AC를 실제 검증했고 관련 구현 PR이 머지됐다. 운영 이슈는 실제 작업 후 닫았다. |
| 코드·설치본 | 최종 통합 상태의 `uv run pytest`, `uv run ruff check .`, `uv run mypy src/`가 종료 코드 0이며, 배포 artifact의 설치·CLI/JSON smoke도 통과했다. |
| 보존 이전 | 동결 기준선과 전체 행/키/필드·수동 상태·통화별 금액·자산 관측을 비교했고 설명 없는 손실/차이와 미해결 중요 격리가 0이다. |
| 운영 전환 | 설치 release/dataset revision, 대상 서비스·소비자, 구 writer 차단과 첫 실제 사용이 확인됐다. |
| 백업·복구 | 전환 후 기록을 포함한 장비 밖 사본을 격리 경로에 복원해 원본 hash·DB integrity/FK·조회 재현을 검증했다. 예약 실행·키 복구·RPO/RTO 측정과 실패 대응이 확인됐다. |
| 가족 재산 기능 | M4의 계좌 확인·부분/과거 자료·요약/상세 중복·평가/거래 구분·정정 사례가 재임포트와 복원 후에도 유지됐다. |
| 후속 확장 | M5의 구매/할부 대사·월 마감·추가 입력 경로 1개의 AC를 실제로 검증했다. |

검사 명령은 현재 CLI와 구현된 계약을 확인해 실행한다. 아직 없는 migration/backup 명령이나 성공 결과를 만들지 않는다. 상세 비공개 검증 보고서에는 실제 실행 명령·시각·프로그램/schema/dataset revision·manifest 식별자와 결과를 남기고 대화에는 민감 값 없는 결과 요약을 출력한다.

관리 상태의 마지막 확인 명령은 다음과 같다. `found: 25`와 빈 `incomplete`가 필요하지만, 이 결과만으로 위 기능·운영 증거를 대체하지 않는다.

```bash
gh issue list --repo sungjunlee/finjuice --state all --limit 1000 \
  --json number,state,stateReason,url \
  --jq '[.[] | select(.number == 355 or (.number >= 425 and .number <= 448))] | {expected:25, found:length, incomplete:[.[] | select(.state != "CLOSED" or .stateReason != "COMPLETED") ]}'
```

각 마일스톤과 에픽은 하위 작업 검증 후 닫고 마지막에 #425를 닫는다. 이슈가 누락되거나 단순 취소/중복 사유로 닫혔다면 위 검사는 완료가 아니다. 이슈 분할 시 원래 이슈에 모든 대체 작업과 보존된 AC를 연결하고 하위 작업의 실제 완료까지 확인한다.

## 한도·막힘·최종 보고

사용자가 별도 토큰·시간 예산을 지정하지 않았다. 임의의 상한이나 자동 과금·사용량 초기화를 설정하지 않고 현재 계정·세션 한도를 따른다. 단계가 끝났다는 이유만으로 전체 목표를 완료 처리하지 않는다.

필수 접근 권한, 복구 가능한 백업 대상/키, 사용자만 아는 사실 또는 외부 장애로 해당 작업을 진행할 수 없으면 원인·영향·필요한 입력과 재개 지점을 남긴다. 독립적으로 가능한 허용 작업은 계속하되 완료 조건을 낮추거나 장애를 완료로 표시하지 않는다. 목표의 blocked 상태와 재시도는 호스트의 실제 규칙을 따른다.

최종 보고에는 완료한 이슈·머지 PR, 실제 설치 release와 dataset/schema revision, 보존 검증·현장 사용·장비 밖 복원 결과, 남은 미확인 사항을 요약한다. 반복적인 '계속할까요' 대신 현재 checkpoint와 다음 행동을 진행 기록에 남긴다.

## 시작 프롬프트

```text
/goal goals/finjuice-ssot.md의 실행 계약과 GitHub sungjunlee/finjuice #425를 기준으로 M1~M5를 끝까지 완료하라. #430부터 시작해 각 단계의 PR·머지, openclaw 실제 배포·데이터 이전, 가족 재산 기능과 장비 밖 백업·복원 검증까지 수행하라. 원본과 수동 기록 및 사용자 변경을 보존하고, 실행 계약의 코드·보존·운영·복구 증거와 25개 범위 이슈의 실제 완료가 대화에 확인될 때만 목표를 완료하라. 이 범위의 구조 변경·필요 의존성 추가·PR·머지·배포·검증된 마이그레이션·백업·복원은 승인하며, 같은 승인을 반복 요청하지 말고 세션이 이어져도 스프린트 기록에서 계속하라.
```

사용 방식 참고: [OpenAI — Follow a goal](https://developers.openai.com/codex/use-cases/follow-goals). 목표를 실제로 시작하려면 위 프롬프트를 별도 메시지로 보낸다.
